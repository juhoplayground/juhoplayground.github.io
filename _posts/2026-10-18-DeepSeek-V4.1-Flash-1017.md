## 개요

[DeepSeek-V4.1-Flash-1017](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017){:target="_blank"}은 DeepSeek-V4.1-Flash의 마이너 업데이트 버전입니다.
추론, 코딩, 에이전트 작업, 시각 이해 벤치마크 전반에서 성능이 향상되었습니다.
동시에 작업 실행 시간과 출력 길이를 줄여 작업당 비용을 낮추는 방향으로 개선되었습니다.
저장소와 모델 가중치는 모두 MIT 라이선스로 공개되어 있습니다.

## 모델 사양

### 아키텍처

DeepSeek-V4.1-Flash-1017은 sparse Mixture-of-Experts(MoE) 모델이며, DeepSeek 최초의 Causal Encoder-Decoder(CED) 아키텍처를 채택했습니다.
총 파라미터는 5,520억 개이고, 입력 처리에는 약 80억 개, 출력 생성에는 약 160억 개의 파라미터만 활성화되어 토큰당 연산량을 줄입니다.
Hugging Face 모델 카드에는 Safetensors 기준 763B 파라미터로 표기되어 있으며, 텐서 타입은 BF16, F32, F8_E4M3, I8입니다.

이미지와 텍스트 임베딩은 사전학습 초기부터 함께 학습되었습니다.
이는 이전의 애드온 방식 비전 실험 모델인 V4 Flash Vision Exp와 구별되는 점입니다.
입력으로 텍스트와 이미지를 받고, 출력은 텍스트입니다.

압축된 KV 캐시를 사용하여 캐시 메모리를 이전 Flash 세대 대비 약 1/4 수준으로 줄였습니다.
모델 카드에 인용된 기술 리포트 제목도 "DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression"입니다.

### 컨텍스트와 기능

| 항목 | 내용 |
|------|------|
| 컨텍스트 윈도우 | 1,048,576 토큰 (1M) |
| 최대 출력 | 393,216 토큰 |
| 입력 모달리티 | 텍스트, 이미지 |
| 출력 모달리티 | 텍스트 |
| 지원 기능 | Function calling, JSON schema 구조화 출력, reasoning 파라미터 |
| 라이선스 | MIT |
| 주요 용도 | 코딩, 터미널 및 컴퓨터 사용 에이전트, 장기 다단계 작업 |

### 가격

OpenRouter 기준 100만 토큰당 가격은 다음과 같습니다.

| 구분 | 가격 (100만 토큰당) |
|------|------|
| 입력 | $0.15 |
| 출력 | $0.60 |
| 캐시 읽기 | $0.003 |

캐싱과 할인 적용에 따라 실제 비용은 더 낮아질 수 있습니다.
OpenRouter에서는 DeepSeek과 inference.net이 프로바이더로 등록되어 있으며, Balanced, Nitro, Floor 라우팅 모드와 프로바이더 지정 및 제외 기능을 제공합니다.
EU 리전 내 라우팅은 현재 지원되지 않습니다.

## 벤치마크 결과

비교 대상은 이전 버전인 DeepSeek-V4.1-Flash와 K3, GLM-5.3, GPT-5.6 Sol, Opus 5입니다.
아래 표에서 1017은 DeepSeek-V4.1-Flash-1017, V4.1은 이전 DeepSeek-V4.1-Flash를 의미합니다.

### 추론과 코딩

| Benchmark | 1017 | V4.1 | K3 | GLM-5.3 | GPT-5.6 Sol | Opus 5 |
|------|------|------|------|------|------|------|
| HLE w/o tools | 42.6 (44.0†) | 36.8 (39.1†) | 43.5 | 42.0† | 44.5 | 56.3 |
| Terminal-Bench 4.0 | 42.3 | 31.2 | 12.6 | 37.9 | 39.9 | 51.8 |
| DeepSWE v1.1 | 77.0 | 74.2 | 67.5 | 66.9 | 73.0 | 74.0 |
| ProgramBench | 29.1 | 20.3 | 17.5 | 19.0 | 23.0 | 37.0 |
| NL2Repo-Bench | 68.2 | 65.4 | 58.0 | 58.0 | 56.8 | 75.3 |

† 표시는 HLE의 텍스트 전용 서브셋 결과입니다.
Terminal-Bench 4.0은 Claude Code 하네스, DeepSWE v1.1은 Mini-SWE-V2 하네스를 사용해 측정했습니다.

Terminal-Bench 4.0에서 31.2에서 42.3으로, ProgramBench에서 20.3에서 29.1로 가장 큰 폭의 향상을 보였습니다.
DeepSWE v1.1에서는 77.0으로 비교 모델 중 가장 높은 점수를 기록했습니다.
반면 HLE, Terminal-Bench 4.0, ProgramBench, NL2Repo-Bench에서는 Opus 5가 더 높은 점수를 보였습니다.

## 사용 방법

### 프롬프트 인코딩

이 모델은 Jinja 형식의 채팅 템플릿을 제공하지 않습니다.
대신 저장소의 `encoding` 폴더에 레퍼런스 Python 구현인 `encoding.py`가 포함되어 있습니다.
이 구현은 다음 기능을 다룹니다.

- 멀티턴 대화
- Tool calling
- Thinking 모드
- 수치형 reasoning effort
- 대화 중간의 system 메시지
- 이미지 인터리빙

프로덕션 환경에서는 Python 바인딩을 제공하는 Rust 라이브러리 모음인 `deepseek-recipe` 사용을 권장합니다.

### 로컬 추론과 권장 샘플링 설정

저장소의 `inference` 폴더에는 가중치 변환과 로컬 추론 코드가 포함되어 있습니다.
모델 카드에는 vLLM, SGLang, Docker Model Runner로 OpenAI 호환 엔드포인트를 띄우는 예시 명령도 함께 제공됩니다.

권장 샘플링 설정은 다음과 같습니다.

| 파라미터 | 권장값 |
|------|------|
| temperature | 1.0 |
| top_p | 1.0 |
| max_tokens | 256K 이상 |

### OpenRouter API

[OpenRouter](https://openrouter.ai/deepseek/deepseek-v4.1-flash-1017){:target="_blank"}에서는 모델 ID `deepseek/deepseek-v4.1-flash-1017`로 호출할 수 있습니다.
엔드포인트는 `POST https://openrouter.ai/api/v1/chat/completions`이며, `Authorization` 헤더에 OpenRouter API 키를 Bearer 토큰으로 전달합니다.
필수 필드는 `model`과 `messages`입니다.

```bash
curl https://openrouter.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "deepseek/deepseek-v4.1-flash-1017", "messages": [{"role": "user", "content": "What is the meaning of life?"}]}'
```

`stream: true`를 지정하면 Server-Sent Events 형식으로 응답하며, `data: [DONE]`이 올 때까지 각 `data:` 청크를 읽으면 됩니다.

지원 파라미터는 다음과 같습니다.

| 분류 | 파라미터 |
|------|------|
| 필수 | model, messages |
| 샘플링 | temperature, top_p, top_k, min_p, seed, stop |
| 페널티 | frequency_penalty, presence_penalty, repetition_penalty, logit_bias |
| 길이 | max_tokens, max_completion_tokens |
| 추론 | reasoning, reasoning_effort |
| 도구 | tools, tool_choice, parallel_tool_calls |
| 출력 형식 | response_format, stream, logprobs, top_logprobs |

비스트리밍 응답은 `id`, `choices`, `usage`(토큰 수와 `cost` 포함)를 담은 Chat Completions JSON 객체입니다.
주요 오류 코드는 다음과 같습니다.

| 상태 코드 | 의미 |
|------|------|
| 400 | 잘못된 요청 또는 지원하지 않는 파라미터 |
| 401 | API 키 누락 또는 유효하지 않음 |
| 402 | 크레딧 부족 |
| 403 | 지출 한도 도달, 키 비활성화, 접근 차단 |
| 404 | 알 수 없는 모델 또는 처리 가능한 프로바이더 없음 |
| 429 | Rate limit, 백오프 후 재시도 |
| 502 | 업스트림 실패, 실패한 생성은 과금되지 않음 |

## 커뮤니티 반응

빠른 토큰 생성 속도와 첫 토큰까지의 시간(TTFT), 명확하게 보이는 chain-of-thought 출력, 갑작스러운 거절이 줄어든 점이 긍정적으로 평가되었습니다.
과도한 설계 없이 개발자가 실제로 작성할 법한 코드를 만든다는 의견과, 가격 대비 가치가 높다는 의견이 여러 차례 나왔습니다.
최상위 모델에 근접한 성능이면 충분하며, 특히 최상위 모델이 지나치게 조심스러운 보안 작업에서 유용하다는 의견도 있었습니다.

반면 대규모 C++ 코드 리뷰에서 GPT-6.1 Sol보다 실행 시간이 훨씬 길고 발견한 이슈도 적었다는 테스트 결과가 공유되었습니다.
해당 사용자는 이 모델에 6.5/10, Sol에 7.5~8/10 점을 매겼습니다.
낮은 reasoning effort에서 비슷한 지능을 유지하면서 출력량은 약 40% 수준이었다는 평가도 있었습니다.

실행마다 결과 편차가 있고, `high` effort가 `max`보다 나은 경우도 있다는 관찰이 공유되었습니다.
테스트 기대값에 코드를 그대로 맞추는 식의 지름길을 택하는 경우가 있다는 지적과, 내장 웹 검색 결과 품질이 일정하지 않다는 의견도 있었습니다.

워크플로 측면에서는 Opus 같은 더 강한 모델로 계획과 리뷰를 맡기고 DeepSeek으로 구현을 담당하게 하는 조합이 여러 차례 언급되었습니다.
서로 다른 모델 계열을 함께 쓰면 발견하는 문제가 겹치지 않아 도움이 된다는 의견도 있었습니다.
중국 기반 프로바이더 사용에 대한 우려와 함께 Fireworks.ai 같은 대안 프로바이더를 제안하는 의견도 나왔습니다.

## 결론

DeepSeek-V4.1-Flash-1017은 마이너 업데이트임에도 Terminal-Bench 4.0, ProgramBench, Apex Bench 등에서 이전 버전 대비 큰 폭의 향상을 보였습니다.
에이전트 벤치마크 3종과 DeepSWE v1.1에서는 비교 모델 중 가장 높은 점수를 기록했지만, 추론과 일부 코딩·비전 항목에서는 Opus 5가 앞섰습니다.
입력 100만 토큰당 $0.15, 출력 $0.60의 가격과 1M 컨텍스트, MIT 라이선스 공개 가중치를 고려하면 코딩과 에이전트 작업의 구현 단계를 담당하는 비용 효율적인 선택지로 활용할 수 있습니다.
