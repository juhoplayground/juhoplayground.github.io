## 개요

[Codex Resets](https://codex-resets.com/){:target="_blank"}는 Codex와 ChatGPT Work의 사용량 제한(usage limit) 초기화 공지를 추적하는 웹 도구다.
초기화 공지는 OpenAI의 공식 릴리스 노트나 상태 페이지가 아니라 @thsottiaux의 트윗을 통해 전달된다.
이 사이트는 해당 계정의 트윗을 모니터링해 초기화 이벤트를 기록하고, 26주 분량의 타임라인과 누적 통계를 함께 제공한다.

사이트는 스스로를 "소프트웨어 업계에서 가장 중요한 트윗 추적기"로 소개하며, "Codex 제한은 @thsottiaux가 초기화한다고 말할 때 초기화된다"는 문구를 내걸고 있다.

## 배경

Codex 사용자는 요금제별 사용량 제한에 도달하면 다음 주기까지 대기해야 한다.
그런데 OpenAI 측은 인시던트 보상, 마일스톤 기념, 기능 출시 등의 사유로 이 제한을 예정 주기와 무관하게 앞당겨 초기화해 왔다.
문제는 이 초기화가 정형화된 공지 채널이 아니라 담당자 개인 계정의 트윗으로만 알려진다는 점이다.

결과적으로 "지금 내 사용량이 초기화됐는지"를 확인하려면 특정 인물의 타임라인을 직접 확인해야 하는 구조가 만들어졌다.
Codex Resets는 이 확인 과정을 자동화한 도구다.

## 핵심 내용

### 추적 통계

사이트가 제공하는 정량 지표는 다음과 같다.

| 지표 | 값 |
|------|-----|
| 누적 초기화 기록 횟수 | 35회 |
| 평균 초기화 간격 | 8.9일 |
| 최장 무초기화 대기 기간 | 67.7일 |
| 최근 초기화 시점 | 2일 전 |
| 타임라인 표시 범위 | 26주 |

평균 간격 8.9일과 최장 대기 67.7일의 차이가 이 이벤트의 성격을 보여준다.
초기화는 고정 주기로 반복되는 스케줄이 아니라, 특정 사건에 반응해 비정기적으로 발생하는 이벤트에 가깝다.
26주 타임라인은 대략 1월부터 7월까지의 구간을 시각화한다.

### 초기화가 발생하는 상황

기록된 공지들을 보면 초기화를 촉발한 사유는 크게 몇 가지 범주로 나뉜다.

| 범주 | 설명 |
|------|------|
| 인프라 인시던트 | 장애 및 서비스 중단에 대한 보상 성격의 초기화 |
| 사용자 마일스톤 | 활성 사용자 300만, 700만, 800만, 900만 달성 기념 |
| 기능 출시 | 신규 기능 및 업데이트 배포에 맞춘 초기화 |
| 성능 이슈 대응 | 캐시 최적화 롤백 등 성능 문제 처리 과정에서의 초기화 |
| 프로모션 | 휴일 등 특정 시점의 프로모션성 초기화 |

즉 초기화는 서비스 운영 상황과 마케팅 이벤트가 혼재된 결과물이며, 사용자가 사전에 예측할 수 있는 규칙성은 존재하지 않는다.

### 알림 채널과 제작자

Codex Resets는 브라우저에서 직접 확인하는 방식과 Telegram 알림 두 가지 접근 경로를 제공한다.
제작자는 [@wong2__](https://x.com/wong2__){:target="_blank"}이며, 사이트에는 "Tibo, if you're reading this: no pressure"라는 문구가 함께 적혀 있다.

사이트는 OpenAI와 무관한 비공식 프로젝트임을 명시하고 있다.
또한 수집된 공지의 분류는 사람이 아니라 자동화된 분류기가 수행한다고 밝히고 있다.

## 의미와 시사점

이 도구가 존재한다는 사실 자체가 하나의 시사점이다.
유료 서비스의 사용량 한도가 변경되는 이벤트가 공식 채널이 아닌 개인 계정의 트윗에만 의존해 전달되고 있으며, 그 공백을 서드파티 추적기가 메우고 있다.

운영 관점에서 보면 사용량 제한 정책의 변경은 예측 가능한 채널로 전달되는 편이 바람직하다.
평균 8.9일 간격과 67.7일의 최장 공백이 공존하는 분포는 이 이벤트를 업무 계획의 변수로 삼기 어렵다는 점을 보여준다.
Codex를 실무에 도입한 팀이라면 초기화를 기대 가능한 자원으로 가정하지 않고, 정규 한도 내에서 작업량을 계획하는 편이 안전하다.

동시에 이 사례는 개발자 커뮤니티가 정보 비대칭을 해소하는 방식도 보여준다.
공식 API나 상태 페이지가 없는 영역에서도 공개 트윗이라는 데이터 소스만 있으면 추적기와 알림 파이프라인을 구성할 수 있다.

## 결론

Codex Resets는 @thsottiaux의 트윗을 모니터링해 Codex 및 ChatGPT Work의 사용량 제한 초기화를 기록하는 비공식 추적기다.
26주간 35회의 초기화가 기록되었고, 평균 간격은 8.9일, 최장 무초기화 기간은 67.7일이다.
초기화 사유는 인프라 장애 보상, 사용자 마일스톤, 기능 출시, 성능 이슈 대응, 프로모션 등으로 다양하며 고정된 주기는 없다.

Codex 사용량 한도에 자주 부딪히는 사용자라면 Telegram 알림을 통해 초기화 시점을 확인하는 용도로 활용할 수 있다.
다만 이 도구는 비공식 프로젝트이며 분류가 자동화되어 있다는 점을 감안해야 한다.
